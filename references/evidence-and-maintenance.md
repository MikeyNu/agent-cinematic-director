# Evidence and maintenance

Use the focused references for routine work. Research only the unresolved feature, contradiction or failure. The foundational filmmaking guidance is intended to remain useful across models; providers, UI controls and connected tool schemas change much faster.

## Trust evidence according to its scope

| Evidence | Use it for | Limit |
| --- | --- | --- |
| Current tool schema and returned catalog | Executable parameter names, allowed inputs, live capability | One account/integration surface is not the whole provider |
| Current official technical documentation | Color transforms, optics, frame timing, format behavior, model mode | Check version and distinguish actual specification from marketing |
| Named creator's account of their own production | Practical choices, workflow and tradeoffs in that production | A successful case does not establish a universal rule |
| First-person community report | A reproducible failure hypothesis or small experiment | Self-report, selection effects, unknown settings, versions and sponsorship |
| Repeated online advice or attractive examples | Ideas to test | Repetition and attractive thumbnails are not causal evidence |
| Actual inspection of your output | Acceptance of the tested artifact under the tested conditions | Do not generalize to uninspected frames, formats or models |

Prefer ASC interviews, filmmaker/animator explanations, lens manufacturers, color-system documentation and the actual tool's documentation over generic lists of cinematic tricks. Read creator blogs and social posts for production pain points. Preserve dates, model/version, evidence type and incentives where disclosed. Label promotional/provider examples and anonymous reports. Do not claim to have watched a linked film when only its page text or transcript was accessible.

## Refresh only what is unstable

Before execution, resolve model identity, supported input/reference roles, duration/resolution/aspect ratio, actual camera/lighting controls, preset session requirements, cost and job state behavior. Search the official current documentation when the connected tool cannot resolve a required capability. Do not import website features into a different API by analogy.

Refresh export/destination requirements when the platform, color target, frame rate, captions or delivery container changes. Do not prescribe a social platform's safe-area pixels or maximum duration from memory.

For a new filmmaking technique, record: **claim, intended benefit, prerequisites, source, evidence scope, failure conditions, cheapest useful comparison, acceptance observation**. Compare one changed variable where possible. Keep a useful failed experiment with its cause/limits so the next task does not repeat it.

## Resolve conflicts explicitly

- Prefer the active schema for whether a request can execute.
- Prefer optics/color specifications for physical facts over a provider's descriptive lens preset.
- Prefer the user's intended style and actual output for creative acceptance over a universal aesthetic rule.
- Preserve unknown source color space rather than assigning camera log by appearance.
- Describe an unverified community method as a hypothesis, not a documented control.
- If the requested constraint cannot coexist with the tool limits, offer the smallest concrete change or a deterministic alternative.

## Maintain the skill without growing the main file

Keep the main workflow lean. Update the specific reference and its dated sources when a fact changes. Remove obsolete IDs from recommendations, retain historical snapshots only when they explain a compatibility lesson, and never cache user balances, private media URLs or access tokens. Add a regression scenario when a real failure exposes a missing instruction.

The references were researched on **2026-11-18**. Their sources are linked near the relevant guidance. [Creator practice](creator-practice.md) records firsthand methods and evidence limits. This maintenance policy and evidence hierarchy are editorial recommendations for reliable agent behavior, not vendor guarantees.
